# ADR 0014: 활동 유형 8종 → 4종, 진로 계열 5종 → 7종

## 상태

확정 (2026-08-08/09, 케빈 요청). **ADR 0003의 taxonomy 결정과 `docs/specs/student-home.md` 확정 F를 대체한다.**

## 배경

케빈: *"프로그램 카테고리가 좀 애매한 것 같다."*

시드 데이터를 뜯어보니 애매함의 정체가 데이터로 드러났다.

### 문제 1 — 한 enum에 축이 두 개 눌려 있었다

`group`(교내/교외 = **어디서** 여는가)과 `name`(방과후/동아리/대회 = **무엇을** 하는가)이 8개 키 안에
섞여 있었다. 결과로 **8종 중 4종이 중복**이었다.

| 중복 | 키 |
|---|---|
| 대회 | `hdc`(교내) / `edc`(교외) |
| 기타 | `het`(교내) / `eet`(교외) |

"대회만 보기" 필터를 걸려면 두 키를 알아야 했다.

### 문제 2 — 진로 앱인데 '진로 체험' 칸이 없었다

"기타" 4건이 **전부 사실은 뚜렷한 유형**이었다.

| 당시 분류 | 실제 제목 | 진짜 성격 |
|---|---|---|
| `het` 교내기타 | 또래 멘토링 프로그램 | 자율활동 |
| `het` 교내기타 | 학생자치회 정책 제안 | 자율활동 |
| `eet` 교외기타 | 대학 전공 체험의 날 | **진로 체험** |
| `eet` 교외기타 | 지역 연계 진로 박람회 | **진로 체험** |

갈 칸이 없어서 기타로 간 것이다.

### 문제 3 — `ecp`(기업·국가기관)만 축이 달랐다

나머지가 "무엇을"인데 이것만 "누가". 그래서 성격이 제각각인 셋이 한 칸에 있었다 —
삼성 SW 아카데미(교육), 카카오 진로 멘토링(멘토링), 교육부 진로체험 캠프(체험).

### 문제 4 — 진로 계열 5종의 구멍

- `it`이 `sci`와 **동급**이었다. IT는 공학의 부분집합이라 "AI 로봇 대회"가 어디인지 애매했다.
- **의약·보건이 없었다.** 고교생 진로 희망 최상위권인데 `sci`로 억지로 들어갔다.
- **교육(사범)이 없었다.** `hum`? 애매.

## 결정

### 결정 1 — 활동 유형 **4종**, 단일 축(무엇을 하는가)

| 키 | 이름 | 포함 |
|---|---|---|
| `school` | 교내 활동 | 동아리 · 자율활동 · 학생회 · 또래멘토링 |
| `contest` | 대회·공모전 | 교내외 모든 대회 |
| `volunteer` | 봉사활동 | 주최 무관 모든 봉사 |
| `career` | 진로 체험 | 박람회 · 학과탐방 · 멘토링 · 기업/대학/기관 프로그램 · 공유학교 · 온라인학교 |

**겹침이 0이다.** 어떤 프로그램이든 갈 곳이 정확히 하나다. 시드 17건이 **5 / 5 / 2 / 5**로 고르게 떨어진다.

- **기타 칸을 만들지 않는다.** 애매한 것이 갈 곳이 생기면 그리로 몰려 분류가 다시 무너진다.
  17건이 기타 없이 전부 들어간다는 것이 4종으로 충분하다는 근거다.
- **교내/교외 축을 폐지한다.** 방과후·교내대회가 빠지면 교내에 동아리·자율만 남아 축으로서 의미가 없다.
- **주최는 카테고리가 아니다.** 기업/대학/국가기관/공유학교/온라인학교 구분은 `programs.org` 텍스트가
  화면에 이미 찍어 준다("삼성전자", "○○대학교", "경기도교육청 공유학교").
  >>> 이걸 카테고리로 다시 나누면 "기업이 여는 진로 박람회"가 두 칸에 걸린다.

### 결정 2 — 방과후를 폐지한다

**참여에 비용이 드는 활동을 포인트로 보상하면 "돈 내고 포인트 사는" 구조가 된다**(케빈).

- 시드 3건(파이썬 코딩 기초 방과후 / AI·데이터 기초 방과후 / 수학 심화 탐구반) 삭제.
- **"수학 심화 탐구반"은 그와 별개로 절대 원칙 2 위반**이었다 — 학업이지 진로·커리어 활동이 아니다.
- 대체 행을 만들지 않았다. 17건은 확정 F(16~20) 안이다.
- >>> 유료 활동을 시드에 다시 넣지 말 것.

### 결정 3 — 대회는 **교내·교외 구분 없이 전부** 받는다

케빈이 제기한 논리 — *"대회는 상장을 받으면 생기부·내신에 영향을 주니 보상 체계가 이미 있다"* — 는
타당하고 기록해 둔다. 그럼에도 대회를 남기는 이유는 **포트폴리오 축으로서 대회가 빠지면 아까워서**다.
교내/교외를 가르지 않는 것은 그 축 자체를 없앴기 때문이다.

### 결정 4 — 봉사활동은 **독립 카테고리**

케빈의 초안은 봉사를 "공공·지역 연계"에 넣었으나 두 가지 이유로 분리했다.

1. **기업이 여는 봉사, 대학이 여는 봉사가 다른 칸으로 갈린다** — 지금 "대회가 두 키로 갈린" 문제의 재발.
2. **생기부에서 봉사는 독립 항목이고 시간이 따로 집계된다.** 아카이브에서 "봉사 몇 건 했지"를
   볼 수 없게 되는 것이 손해다.

### 결정 5 — 박람회는 '대회'가 아니라 '진로 체험'

**학생이 하는 행동이 정반대다.** 대회는 준비하고 경쟁하고 수상, 박람회는 둘러보고 상담받기.
준비 기간도 포인트도 다르게 매겨진다. 아카이브에 "대회 및 박람회 6건"으로 찍히면 심사자가 뭘 했는지 모른다.

### 결정 6 — 진로 계열 **7종**

| 키 | 이름 | 변경 |
|---|---|---|
| `hum` | 인문·어학 | 이름만 (구 '인문·사회') |
| `soc` | 사회·교육 | **신설** |
| `biz` | 상경·경영 | 이름만 (구 '경영·경제') |
| `sci` | 자연과학 | 이름만 (구 '이공계·자연과학') |
| `eng` | 공학·IT | **`it` 흡수** |
| `med` | 의약·보건 | **신설** |
| `art` | 예술·체육 | 그대로 |

- `biz`는 대학 계열 구분상 사회계열 안이지만 지망 규모가 커서 별도 축이 실용적이다.
- **`biz` 색을 바꿨다.** 구 `#475569`는 회색이라 계열 색으로서 존재감이 없었다.
- **선언 순서가 곧 화면 순서다.** 레이더 축·요약 분포가 이 순서를 그대로 쓴다.
  값 크기순으로 정렬하면 그 순간 순위표가 된다(원칙 1).

## 구현 — enum **값 추가가 아니라 타입 교체**

Postgres enum은 값을 제거·개명할 수 없다. 그래서 새 타입을 만들고 컬럼을 옮긴 뒤 옛 타입을 지운다.

>>> ADR 0013의 "enum 확장은 단독 마이그레이션" 규율은 `alter type ... add value`에만 해당한다.
> 여기처럼 **새 타입을 만들어 같은 트랜잭션에서 쓰는 것은 55P04 제약과 무관하다.**

**`career_track`은 컬럼 두 개가 공유한다**(ADR 0003 결정 3) — `programs.career_track` +
`profiles.career_interest`. 한쪽만 옮기면 옛 타입을 drop할 수 없다. 또 `set_career_interest(p_track
public.career_track)`이 타입에 의존하므로 **먼저 드롭하고 나중에 되만든다.**

**재실행 안전**: `case` 문에 신규 값의 **항등 매핑**이 들어 있다.
>>> 항등 매핑 줄을 지우지 말 것. 지우면 재실행이 모든 행을 `else`로 몰아 파괴적으로 바뀐다.

## 화면 영향 — `CAT[].group`이 8곳에서 쓰이고 있었다

`group`을 없애면서 전부 손봤다. 대부분 `${group} · ${name}` → `${name}`이지만 두 곳은 구조가 바뀌었다.

### `StudentProgramsPage` — 카테고리 그룹 2개가 사라졌다

'학교 내 활동' / '학교 외 활동' 두 묶음으로 8종을 나눠 그렸는데(프로토타입 904줄) 그 묶음의 근거가
없어졌고, 4종이라 한 화면에 다 들어간다. 남는 구분은 **"참여할 수 있는 것 / 날짜가 지난 것"** 하나뿐이다.
>>> CAT을 다시 묶는 그룹 배열을 만들지 말 것.

### `StackViz` — 블록 색 기준이 사라졌다

교내 = brand blue / 교외 = indigo 였다. **활동 유형(CAT) 색**으로 바꿨다 — 캘린더 팝업의 날짜 점이
이미 계열 색을 쓰므로 같은 언어를 따른다. 블록 색이 "무슨 활동이었는지"를 말한다.

- **amber 금지는 그대로다.** CAT 4종 색에 amber가 없는 것이 그 가드다.
  (구 8종에는 교내 대회가 amber `#E0922F`였는데, 4종으로 줄면 비중이 커져 "대회=포인트"로 읽힌다.)
- **그림자는 색을 따라가지 않고 중립 잉크 톤으로 고정**했다. 유형별로 그림자까지 갈리면 블록이
  "빛나는 정도"로 읽혀 성취 연출이 된다(원칙 1).

### `ArchiveSummary` — '교내 활동 / 교외 활동' 2칸의 근거가 사라졌다

`catKinds`(경험한 활동 유형 수) + `monthSpan`(활동한 개월 수)로 대체했다.
**둘 다 분모 없는 개수다** — "4종 중 3종"처럼 분모를 붙이면 그 순간 달성률이 되고 화면이 게이지를 그린다.
>>> `summarizeActivities()`가 분모를 함께 내보내게 만들지 말 것.

## 절대 원칙 체크

- **원칙 1**: 새 지표가 0개다. `catKinds`/`monthSpan`은 분모 없는 개수이고, StackViz는 여전히
  숫자·레벨·게이지가 없다. CAT 색에서 amber를 뺀 것이 오히려 가드를 강화했다.
- **원칙 2 (학업 아닌 진로)**: "수학 심화 탐구반"이라는 **실제 위반 데이터를 제거**했다. 방과후 폐지로
  학업 보충 성격의 칸 자체가 없어졌다.
- **원칙 4**: amber가 이제 포인트 전용이다.
- **원칙 6**: 관리자 동작 0개 추가. 등록 폼의 드롭다운 선택지가 8개에서 4개로 **줄었다.**

## 알려진 사항

- **`med`(의약·보건)에 시드가 0건이다.** 방과후 3건을 삭제하면서 대체 행을 만들지 않았기 때문이다.
  레이더는 0인 축도 그린다("무엇을 아직 안 했는가"까지 읽히는 게 값 — `summarizeByTrack` 주석)이므로
  화면이 깨지지는 않는다. 의료 계열 프로그램을 넣고 싶으면 시드에 1건 추가하면 된다.
- **원격 DB의 기존 방과후 행은 마이그레이션이 지우지 않는다.** 참여·포인트가 딸려 있을 수 있어
  데이터 삭제를 마이그레이션이 조용히 할 일이 아니다. `career`로 옮겨두고 수동 정리 SQL을 파일 끝에 적었다.
- **과거 날짜 fixture가 옮겨졌다.** "수학 심화 탐구반"이 유일한 과거 행이었는데 삭제되면서
  "하천 환경 정화 봉사"(dayOffset 16 → -6)가 그 역할을 받았다. 이미 끝난 활동으로 자연스럽다.
